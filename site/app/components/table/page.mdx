## A table

`Table` composes the same way as `Card`. The wrapper handles overflow and the sticky
head; you give it a `maxHeight` and the header stays put while the body scrolls.

<TableDemo code={`
<Table.Wrap maxHeight={260}>
  <Table zebra>
    <Table.Head>
      <Table.Tr>
        <Table.Th>Order</Table.Th>
        <Table.Th>Customer</Table.Th>
        <Table.Th>Warehouse</Table.Th>
        <Table.Th num>Qty</Table.Th>
      </Table.Tr>
    </Table.Head>
    <Table.Body>
      {[
        ['ORD-880241', 'Reliance Fresh', 'BLR-01', 140],
        ['ORD-880242', 'Big Basket', 'DEL-02', 24],
        ['ORD-880243', 'Quick Comm', 'MUM-04', 8],
        ['ORD-880244', 'DMart', 'HYD-03', 312],
      ].map(([id, cust, wh, qty]) => (
        <Table.Tr key={id}>
          <Table.Td id>{id}</Table.Td>
          <Table.Td>{cust}</Table.Td>
          <Table.Td muted>{wh}</Table.Td>
          <Table.Td num>{qty}</Table.Td>
        </Table.Tr>
      ))}
    </Table.Body>
  </Table>
</Table.Wrap>
`} />

Three cell props carry most of the weight:

| Prop | What it does |
| --- | --- |
| `id` | Sets the cell in the identifier face — SKUs, order IDs, bins |
| `num` | Right-aligns and uses tabular figures, so a column of numbers lines up |
| `muted` | Secondary text, for context that shouldn't compete with the data |

## Sorting is driven by ARIA

`sort` sets `aria-sort` on the header, and the arrow is drawn **from** that attribute
rather than beside it. So the state a screen reader announces and the state you can see
are the same state — they cannot disagree, because there is only one.

<TableDemo code={`
function SortableTable() {
  const [dir, setDir] = useState('ascending');
  const rows = ['SKU-2288-NVY-S', 'SKU-4417-BLK-M', 'SKU-9120-WHT-L'];
  const sorted = dir === 'ascending' ? rows : [...rows].reverse();
  return (
    <Table.Wrap>
      <Table>
        <Table.Head>
          <Table.Tr>
            <Table.Th sort={dir} onSort={() => setDir(d => d === 'ascending' ? 'descending' : 'ascending')}>
              SKU
            </Table.Th>
            <Table.Th num>On hand</Table.Th>
          </Table.Tr>
        </Table.Head>
        <Table.Body>
          {sorted.map((sku, i) => (
            <Table.Tr key={sku}>
              <Table.Td id>{sku}</Table.Td>
              <Table.Td num>{[42, 17, 308][i]}</Table.Td>
            </Table.Tr>
          ))}
        </Table.Body>
      </Table>
    </Table.Wrap>
  );
}
`} noInline={false} />

## Row state

`selected` marks a row the user has chosen. `severity` marks one the *system* wants
attention on — a breach, a short pick. They are different ideas and should not be
rendered the same way, which is why they are separate props rather than one `variant`.

<TableDemo code={`
<Table.Wrap>
  <Table>
    <Table.Body>
      <Table.Tr selected>
        <Table.Td id>ORD-880241</Table.Td><Table.Td>Selected by the user</Table.Td>
      </Table.Tr>
      <Table.Tr severity="danger">
        <Table.Td id>ORD-880242</Table.Td><Table.Td>SLA breached</Table.Td>
      </Table.Tr>
      <Table.Tr severity="warning">
        <Table.Td id>ORD-880243</Table.Td><Table.Td>Short pick</Table.Td>
      </Table.Tr>
    </Table.Body>
  </Table>
</Table.Wrap>
`} />

## Density

`compact` is for tables a warehouse lead scans all day; `comfortable` is for tables
with wrapping text. The default sits between them. Warehouse mode raises all three —
switch it above and watch the rows open up.

<TableDemo code={`
<Table.Wrap>
  <Table density="compact">
    <Table.Head>
      <Table.Tr><Table.Th>Bin</Table.Th><Table.Th num>Qty</Table.Th></Table.Tr>
    </Table.Head>
    <Table.Body>
      {['A-12-03', 'C-04-11', 'B-21-07'].map((bin, i) => (
        <Table.Tr key={bin}>
          <Table.Td id>{bin}</Table.Td><Table.Td num>{[4, 2, 1][i]}</Table.Td>
        </Table.Tr>
      ))}
    </Table.Body>
  </Table>
</Table.Wrap>
`} />

## Empty states

`Table.Empty` spans the table and centres its message. An empty table should say why it
is empty and what to do — “No orders match these filters” is useful; “No data” is not.

<TableDemo code={`
<Table.Wrap>
  <Table>
    <Table.Head>
      <Table.Tr><Table.Th>Order</Table.Th><Table.Th>Status</Table.Th></Table.Tr>
    </Table.Head>
    <Table.Body>
      <Table.Empty colSpan={2}>
        No orders match these filters. Try widening the date range.
      </Table.Empty>
    </Table.Body>
  </Table>
</Table.Wrap>
`} />

## When not to use a table

Two columns and four rows is a description list, not a table. And if the columns are
only ever read one row at a time, cards may serve better — a table earns its structure
when people compare *down* a column.
