# Modal

<div className="lede">
Built on the platform's own `<dialog>` opened with `showModal()`. The focus trap,
Escape, the inertness of everything behind it, the top layer and returning focus when
it closes are all the browser's job. We add the scroll lock and the design.

## Built on the platform, not on us

The dashboard had nine hand-rolled modals — `fixed inset-0` with a hand-picked
z-index — and between them they got the focus trap wrong, forgot Escape, and left the
page scrolling underneath. None of that is a thing anyone should be reimplementing.

Open it and try Escape, or Tab round the edges — nothing in that behaviour is ours.

## Sizes and shapes

`size` covers the width. `variant` changes the shape entirely: a `drawer` slides from
the edge for filters and detail panels, a `sheet` rises from the bottom for touch.

## Destructive confirmations ignore the backdrop and Escape

`alert` makes it an `alertdialog`, and deliberately makes it *harder* to dismiss: a
stray click on the backdrop or a reflexive Escape should not be how someone deletes a
rule. The only ways out are the two buttons, which is the whole point of asking.

<ModalDemo code={`
function Demo() {
  const [open, setOpen] = useState(false);
  return (
    <>
      <Button variant="danger" onClick={() => setOpen(true)}>Delete rule</Button>
      <Modal open={open} onClose={() => setOpen(false)} alert size="sm"
             title="Delete this rule?"
             subtitle="Orders currently matching it will fall through to the default.">
        <ModalFooter>
          <Button variant="secondary" onClick={() => setOpen(false)}>Keep it</Button>
          <Button variant="danger" onClick={() => setOpen(false)}>Delete</Button>
        </ModalFooter>
      </Modal>
    </>
  );
}
render(<Demo />);
`} />

## The scroll lock follows `open`

Worth knowing if you read the source: the lock is its own effect keyed on the `open`
prop, not something done next to `showModal()`. Paired with the call, React's
double-invoked effects could release it while the dialog was still on screen — a modal
over a page that still scrolled. Tying it to the prop makes it idempotent.

## When not to use a modal

A modal interrupts. If the task is the main thing the person came to do, it wants a
page. If it is a message rather than a decision, it wants a toast or an inline notice.
Reach for a modal when you genuinely need an answer before anything else can continue —
and never stack one on another.
