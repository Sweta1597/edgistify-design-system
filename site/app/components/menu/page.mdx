# Menu &amp; Select

<div className="lede">
Five components sharing one panel. They differ in what an item **means**, not in how
the panel behaves — and every panel is a native `popover`, so the top layer, light
dismissal and Escape all come from the browser.
</div>

| | Role | The value is |
| --- | --- | --- |
| `Menu` | `menu` / `menuitem` | nothing — an action ran |
| `Select` | `listbox` / `option` | one option |
| `MultiSelect` | `listbox` + `aria-multiselectable` | many options |
| `CascadeSelect` | columns, each a `listbox` | a **path** |
| `TreeSelect` | `tree` / `treeitem` | a **node** |

## Menu — items are actions

<MenuDemo code={`
<Menu
  trigger={<Button variant="secondary">Row actions</Button>}
  items={[
    { label: 'View order', onSelect: () => {} },
    { label: 'Split order', onSelect: () => {} },
    { type: 'separator' },
    { label: 'Cancel order', danger: true, onSelect: () => {} },
  ]}
/>
`} />

## Select — one option

Searchable when the list is long enough to need it. Open it and use the arrow keys:
the highlight is driven by `aria-activedescendant`, so the pointer and the keyboard can
never light up two different rows.

<MenuDemo code={`
function Demo() {
  const [value, setValue] = useState('blr-01');
  return (
    <Select
      searchable
      value={value}
      onChange={setValue}
      options={[
        { value: 'blr-01', label: 'BLR-01 Bommanahalli', meta: '2,140 SKUs' },
        { value: 'del-02', label: 'DEL-02 Bhiwandi', meta: '1,804 SKUs' },
        { value: 'hyd-03', label: 'HYD-03 Medchal', meta: '920 SKUs' },
        { value: 'mum-04', label: 'MUM-04 Panvel', meta: '3,006 SKUs', disabled: true },
      ]}
    />
  );
}
`} noInline={false} />

## MultiSelect — many options

Chips up to `maxTokens`, then a count. The footer selects and clears everything
currently matching the search, not everything in the list — which is what people
expect after they have typed something.

<MenuDemo code={`
function Demo() {
  const [value, setValue] = useState(['amazon', 'flipkart']);
  return (
    <MultiSelect
      searchable
      maxTokens={2}
      value={value}
      onChange={setValue}
      placeholder="All channels"
      options={[
        { value: 'amazon', label: 'Amazon' },
        { value: 'flipkart', label: 'Flipkart' },
        { value: 'myntra', label: 'Myntra' },
        { value: 'nykaa', label: 'Nykaa' },
        { value: 'ajio', label: 'Ajio' },
      ]}
    />
  );
}
`} noInline={false} />

## CascadeSelect — the value is a path

Use it when depth is even and **the path is the answer**. A bin is always
warehouse → zone → aisle → bin and you want all four, so the chosen path is shown
above as a sentence rather than three highlighted rows you have to reassemble.

<MenuDemo code={`
function Demo() {
  const [path, setPath] = useState([]);
  return (
    <CascadeSelect
      leafOnly
      value={path}
      onChange={setPath}
      placeholder="Pick a bin"
      options={[
        { value: 'blr', label: 'BLR-01', children: [
          { value: 'z-a', label: 'Zone A', children: [
            { value: 'a-12', label: 'Aisle 12', children: [
              { value: 'a-12-03', label: 'Bin 03' },
              { value: 'a-12-04', label: 'Bin 04' },
            ]},
          ]},
        ]},
        { value: 'del', label: 'DEL-02', children: [
          { value: 'z-c', label: 'Zone C', children: [
            { value: 'c-04', label: 'Aisle 04', children: [
              { value: 'c-04-11', label: 'Bin 11' },
            ]},
          ]},
        ]},
      ]}
    />
  );
}
`} noInline={false} />

## TreeSelect — the value is a node

Use it when depth is uneven and only **the node** matters. A category tree stops where
it stops; columns would leave gaps.

## Popover — for a dropdown a screen already owns

The five above own their own state and markup. `Popover` owns neither: a screen keeps
the `open` flag it already had and puts inside whatever it already rendered. It exists
so an existing hand-positioned panel can move into the top layer without its behaviour
being rewritten.

<MenuDemo code={`
function Demo() {
  const d = useDropdown();
  const [picked, setPicked] = useState('All locations');
  return (
    <div>
      <button {...d.triggerProps} className="ed-btn ed-btn--secondary">{picked}</button>
      <Popover {...d.popoverProps} className="min-w-[220px]">
        <div className="ed-pop__list" role="listbox">
          {['All locations', 'BLR-01 Bommanahalli', 'DEL-02 Bhiwandi'].map(l => (
            <button key={l} role="option" aria-selected={picked === l}
              className="ed-pop__item"
              onClick={() => { setPicked(l); d.close(); }}>{l}</button>
          ))}
        </div>
      </Popover>
    </div>
  );
}
`} noInline={false} />

The trigger's click handler has to come from `useDropdown`. Light dismissal fires on
`pointerdown` and the click lands after it, so an unguarded trigger would close the
panel and immediately reopen it — it would look stuck open.

## Don't use these when a native select will do

The dashboard has 44 native selects holding 88 options between them — under three
each. A native `<select>` is better for every one of those: smaller,
keyboard-complete, and on a phone it opens the OS picker. `Select` here earns its place
when the list needs searching or an option needs more than a line.
