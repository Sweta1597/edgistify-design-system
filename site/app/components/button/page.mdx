# Button

<div className="lede">

## Seven variants

The variant answers one question: **how much does this action want to be noticed?**
A screen with three primary buttons has answered it wrong.

<ButtonDemo code={`
<ButtonGroup>
  <Button>Confirm pick</Button>
  <Button variant="secondary">Cancel</Button>
  <Button variant="ghost">Details</Button>
  <Button variant="link">View history</Button>
</ButtonGroup>
`} />

| Variant | Use it for |
| --- | --- |
| `primary` | The one action the screen exists for |
| `brand` | Full-strength `#00a699`. At most one per screen, usually none |
| `secondary` | The alternative to primary — cancel, back, a second path |
| `ghost` | Actions that sit in rows and shouldn't compete, like table row actions |
| `danger` | Destructive, standing alone |
| `danger-quiet` | Destructive, sitting in a row of ordinary actions |
| `link` | Navigation wearing a button's clothes |

### Destructive actions

Two variants, and the difference is context rather than severity. `danger` is for a
destructive action standing on its own, where it needs to be unmistakable.
`danger-quiet` is for one sitting in a row of ordinary actions, where a wall of red
would make everything beside it harder to read.

<ButtonDemo code={`
<ButtonGroup>
  <Button variant="danger">Delete rule</Button>
  <Button variant="danger-quiet">Remove</Button>
</ButtonGroup>
`} />

## Five sizes

`md` is the default and the one to reach for. `xl` exists for gloved hands — see
warehouse mode below.

<ButtonDemo code={`
<ButtonGroup>
  <Button size="xs">Extra small</Button>
  <Button size="sm">Small</Button>
  <Button>Medium</Button>
  <Button size="lg">Large</Button>
  <Button size="xl">Extra large</Button>
</ButtonGroup>
`} />

## Loading and disabled

`loading` keeps the button's width stable while it spins, so the row beneath it
doesn't jump. It also blocks input and sets `aria-busy`, so the state is announced
rather than merely drawn.

<ButtonDemo code={`
<ButtonGroup>
  <Button loading>Saving</Button>
  <Button disabled>Unavailable</Button>
  <Button variant="secondary" disabled>Unavailable</Button>
</ButtonGroup>
`} />

Disabled controls are deliberately exempt from the contrast floor — WCAG 1.4.3
excludes inactive controls, and a disabled button that meets 4.5:1 doesn't look
disabled. What it must never do is be the only explanation: if a button is disabled,
something on screen should say why.

## Icon-only

An icon is not an accessible name. `icon` requires `aria-label`, and the component
warns in development if you forget — the target also grows invisibly to meet the
minimum touch size even when the button is drawn smaller.

<ButtonDemo code={`
<ButtonGroup>
  <Button icon aria-label="Print label" variant="secondary">
    <svg viewBox="0 0 24 24" fill="none" stroke="currentColor" strokeWidth="2"
         strokeLinecap="round" strokeLinejoin="round" aria-hidden="true">
      <path d="M6 9V2h12v7M6 18H4a2 2 0 0 1-2-2v-5a2 2 0 0 1 2-2h16a2 2 0 0 1 2 2v5a2 2 0 0 1-2 2h-2" />
      <path d="M6 14h12v8H6z" />
    </svg>
  </Button>
  <Button icon aria-label="Delete" variant="danger-quiet">
    <svg viewBox="0 0 24 24" fill="none" stroke="currentColor" strokeWidth="2"
         strokeLinecap="round" strokeLinejoin="round" aria-hidden="true">
      <path d="M3 6h18M8 6V4h8v2M19 6l-1 14H6L5 6" />
    </svg>
  </Button>
</ButtonGroup>
`} />

## Warehouse mode

Switch **Warehouse** at the top of this page and nothing in the markup changes.
Controls grow to gloved targets, the type floor rises, and `ButtonGroup` with
`stack` turns a row into full-width buttons with the confirming action nearest the
thumb.

<ButtonDemo code={`
<ButtonGroup stack>
  <Button variant="secondary" size="xl">Cancel</Button>
  <Button size="xl">Confirm pick</Button>
</ButtonGroup>
`} />

The 44px and 56px targets here are judgment, not a citable specification. WCAG's
24px (AA) and 44px (AAA) both assume a bare fingertip; nothing in the standard
covers a gloved one.

## When not to use a button

If it navigates, it is a link. Render it as one and it keeps the browser's
behaviour — middle-click, open in a new tab, the status bar preview — none of
which a `<button>` with an `onClick` gives back.

<ButtonDemo code={`
<Button as="a" href="/components/button" variant="link">
  Read the Button page
</Button>
`} />
