Edgistify Design System · Component 06

Menu and Select

Five components, one floating panel. They differ in what an item means, not in how the panel behaves — and every panel is a native popover, so the browser owns the top layer, light dismissal and Escape.

What an item means

The dashboard’s panels sit at z-20, z-30 and z-50 depending on who wrote them. In the top layer there is nothing to sort out.

Menu
role=menu / menuitem
Items are actions. Nothing is “selected” afterwards — the panel closes and something happened.
Select
role=listbox / option
One value. Searchable, because the reason not to use a native select is usually length.
MultiSelect
listbox + aria-multiselectable
Many values. Chips in the trigger, select-all in the footer, a live count.
CascadeSelect
columns, each a listbox
The value is a path. Each column is the chosen parent’s children.
TreeSelect
role=tree / treeitem
One node in a hierarchy, expanded in place with aria-level and aria-expanded.
RULE 12

Don’t reach for these when a native <select> will do. The dashboard has 44 selects holding 88 options between them — under three each. Native is smaller, keyboard-complete, and on a phone it opens the OS picker, which beats anything we can draw.

Use Select here when the list is long enough to need searching, or when an option needs more than a line of text. The styled native <select> shipped with the input family covers the rest.

Warehouse → zone → aisle → bin. Columns rather than nested menus, because a path reads more easily across than down, and the chosen path sits above them as a sentence instead of three highlighted rows you have to reassemble.

Tree — one node in a hierarchy
Category

value: —

The same data could be a cascade, but a category tree has uneven depth — some branches stop at two levels, some go four. Columns would leave gaps; expanding in place shows the shape.

Cascade or tree?

Both hold hierarchical data. They answer different questions.

CascadeSelect
value = ['BLR-01','A','A-12','A-12-03']
Even depth, and every level is a real choice. Bin locations always have exactly four. You are narrowing down, and the path itself is the answer.
TreeSelect
value = 'apparel-tops-tees'
Uneven depth, and only the node matters. A category tree stops where it stops. You are locating one thing, and its ancestors are context rather than part of the value.

API

import { Menu, Select, MultiSelect, CascadeSelect, TreeSelect }
  from '@edgistify/design-system/react/Menu';
import '@edgistify/design-system/menu.css';

<Menu trigger={<Button variant="secondary">Actions</Button>} items={[
  { label: 'Open order', onSelect: open },
  { label: 'Split',      onSelect: split, hint: 'Into 2 shipments' },
  { type: 'separator' },
  { label: 'Cancel order', danger: true, onSelect: cancel },
]} />

<Select options={suppliers} value={v} onChange={setV} />
<MultiSelect options={channels} value={vs} onChange={setVs} maxTokens={3} />

// path: ['BLR-01','A','A-12','A-12-03']
<CascadeSelect options={bins} value={path} onChange={setPath} />

// node: 'apparel-tops-tees'
<TreeSelect options={categories} value={cat} onChange={setCat}
            defaultExpanded={['apparel']} />

Hitting it twice meant it was a missing token, not a bug. There is now an --ed-on-brand-subtle role, and the ghost button uses it too — by name this time rather than by coincidence.
