Edgistify Design System · Component 02

Card

Composable by slot, not driven by props — because the dashboard already has a <Card title subtitle action> used 48 times and bypassed by 101 inline card divs. That is an API problem, not a discipline one.

Why the old one gets bypassed

A card with fixed title/subtitle/action props and a permanent p-4 cannot express a full-bleed table, a clickable tile, a modal shell or a card inside a card. So people write a div — and the radius drifts: rounded-lg, rounded-xl, rounded-2xl and rounded-md all appear meaning “card”. Slots fix it. Nothing is required except the container.

.ed-cardThe container. Surface, border, radius, elevation-1.
__headerTitle block and actions, side by side. `ruled` adds a rule — only when the body bleeds.
__title / __subtitleSemibold 14 and muted 11. The subtitle is optional.
__actionsButtons in the header. Stays flush right as the title wraps.
__bodyPadded content, stacked with --ed-gap-stack.
__bleedEscapes the body padding so a table reaches the edges.
__footerSunken tray, actions right-aligned. `spread` pushes them apart.
__dividerA rule that spans the full card width from inside the body.
__linkStretches one real link across the card. See RULE 06.

RULE 06

A clickable card still needs one real link inside it. <CardLink> stretches across the whole card with a pseudo-element, so the card is clickable while the link keeps the accessible name and the card’s text stays selectable. A div with an onClick is invisible to a screen reader and cannot be tabbed to.

Tab into the interactive card above — the focus ring lands on the card, not on a nested box.

Bleed

A table, chart or image reaching the card’s edges. This is what the 15 overflow-hidden card divs in the dashboard were working around.

Stat tiles

Lead with big numbers only when the figures are the point of the view. A row of them above content that does not need them is decoration.

Direction is the arrow · sentiment is the colour

RULE 07

An arrow is not a sentiment. Returns rising is bad news; fill rate rising is good news; both point up. direction draws the arrow and sentiment picks the colour, because only the caller knows which way is good for that particular number.

Not everything is a card

Border, fill, radius and shadow each announce “separate object”. Spend them on the one thing that needs lifting. The same three rows, twice.

API

import { Card, CardHeader, CardBody, CardBleed, CardFooter, CardStat }
  from '@edgistify/design-system/react/Card';
import '@edgistify/design-system/card.css';

<Card>
  <CardHeader title="Short picks" subtitle="Needs override" ruled
                actions={<Button size="xs" variant="ghost">Export</Button>} />
  <CardBody bleed><table …/></CardBody>
  <CardFooter><Button size="sm">Request override</Button></CardFooter>
</Card>

// clickable — CardLink carries the accessible name
<Card interactive accent="warning">
  <CardBody><CardLink href="/waves/4471">Wave 4471</CardLink></CardBody>
</Card>

// arrow and colour are separate decisions
<CardStat label="Returns" value="312" delta="8.4%" direction="up" sentiment="bad" />
